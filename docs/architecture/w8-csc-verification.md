# W8 — opt-in curvature-bounded CSC shortcut milestone (2026-10-26)

**Status:** implemented and locally tested in the reconstructed C++20 core;
real-OMPL-enabled integration and full remote checkout builds remain unverified.
The CSC generator is an **optional post-search** proposal source for
`ackermann::refinePath()`, not a replacement planner or safety certificate.
See [current implementation](current-implementation.md) and the
[original W8 refiner evidence](w8-refinement-verification.md).

## New API and default

```cpp
#include "hybrid_astar/ackermann/refinement.hpp"
hybrid_astar::ackermann::RefinementOptions options;
options.useCurvatureBoundedShortcuts = true; // default is FALSE
auto final = hybrid_astar::ackermann::refinePath(request, validatedPlan, {}, options);
```

The independent function `generateCurvatureBoundedShortcuts(start, end, Rmin)`
returns up to eight deterministic **fixed-gear** left/straight/right
connections, ordered by geometric length: four CSC turn pairs (LSL, LSR, RSL,
RSR) forward, and four reverse. Degenerate zero-length arc/straight sections
are removed. Every output is constructed using the existing
`MotionSection::evaluate` closed-form Ackermann evaluator and checked against
the requested endpoint to a configurable positional tolerance (default 1e-6 m)
and 1e-6 rad heading tolerance.

For the forward problem, the start/end turn-circle centers for turn sign
`t` are `C = position + t*R*(-sin(yaw),cos(yaw))`. For circle-center
difference `d`, the forward straight heading `H` solves

```text
cross(d, unit(H)) = (startTurn - endTurn)*R
H = angle(d) + asin((startTurn - endTurn)*R/|d|)
straightLength = sqrt(|d|^2 - ((startTurn - endTurn)*R)^2)
```

The two turning angles are the nonnegative turn-direction deltas between
start yaw, straight heading and goal yaw. Reverse-only geometric candidates
are generated by solving the forward problem with headings rotated by pi,
then reversing the physical steering-curvature sign. This retains exact
Ackermann kinematic geometry and positive section progress.

**Not implemented by this generator:** Dubins three-circle (CCC) families,
Reeds–Shepp switching-gear paths, steer-rate-limited interpolation,
numerical curvature-continuous smoothing, moving obstacle clearance, or
continuous swept-body certification. Other exact signed path candidates can
still be injected through `RefinementConnector` (OMPL if available).

## Independent acceptance gate and cost pruning

For each section-boundary window, the refiner inspects the bounded candidate
list. Every candidate is reconstructed as the complete prefix + replacement
+ suffix. The refiner retains its strict independent **full footprint** exact
pose sampling, goal check, actual weighted cost recomputation, and same
map/policy provenance checks, without EDT decisions. It changes the returned
path only for a strict configured cost improvement. The last independently
validated path is preserved on failed proposals, work limit or cancellation.

A new fast rejection computes the **base weighted cost of the complete
candidate** (forward/reverse distance and gear switches) BEFORE strict
collision sampling. Because configured clearance costs are nonnegative,
the base cost is a valid lower bound on the full objective. If the bound
cannot beat the incumbent by `minimumCostReductionMeters`, the candidate
is safely skipped. `RefinementResult::prunedByCostLowerBound` reports this.
The total exact-check budget is not weakened.

These checks do not prove completeness, the global shortest Dubins path,
swept safety, or actuator feasibility. `trajectoryActuatorFeasible`
remains false.

## Local verification

`curved_shortcuts_test` runs **2,000 seeded random target poses**, checks
every returned forward/reverse candidate for exact endpoint, bounded
curvature, direction consistency, ordered lengths, and finite positive arc
progress. It also verifies a curved forward–reverse–forward path is improved,
that the previous straight-only default is unchanged, that unsafe input
is rejected, and that exact-pose work remains bounded. Older scenario,
strict-validation, and refinement suites continue to run.

additional compute on unproductive windows. The native mode remains
**disabled by default** pending representative parking/reverse-heavy maps,
comparison to real OMPL RS, and multi-seed end-to-end p50/p95/p99 studies.
